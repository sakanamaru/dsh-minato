# 退出码裁决（2026-10-30 · EXIT-02 · 政策 A：全量裁决并补齐）

> 范围：`v3/src` 当前 HEAD 上全部 `*_FAIL` / `*_REFUSED` 打印点（本次实测 **26 族 / 100 点**，含 4 个 `BRIDGE_FAIL_RAW` 类诊断点）。
> 规则（用户裁决，写死）：成功 / 计划 / 只读预览 = **0**；执行失败 = **1**；用法错误 = **2**；自完整性拒绝 = **3**；
> **明确降级 / 跳过保持 0**（`RESTORE_WS_SKIPPED` / `INTEGRITY_SKIPPED` / `PROFILECHK_SKIPPED_VENDOR` / `BRIDGE_FAIL_RAW` 等诊断行）。
> 纪律：本批**只改 return 码与必要的 stderr 说明**；标记行文本一个字不动、不新增/不删除标记行、成功/计划路径的 rc 不动。

## 判定口径（先说清"为什么是 1 还是 2"）

- **2（用法错误）**：参数缺失 / 取值不合法 / 参数互斥 —— 命令在**做任何事之前**就拒绝，改参数即可重试。
  既有先例：`config-set` 未知键 = 2、`backup-dir` 相对路径 = 2。
- **1（执行失败或拒绝）**：参数合法，但**环境/前置条件不满足**（没装 dsh、没有备份、端口被占、只读、外部命令失败）
  或**安全拒绝**（会停错进程等）。既有先例：`restore --dry-run` 无有效备份 = 1、`wipe` 缺 --yes = 1。
- **0（降级/跳过/计划）**：明确写"降级"或"不适用"的路径（如无桌面端可停时如实 SKIP、装不上时给出手动指引）
  —— 本批只有**诊断行**保持 0：`BRIDGE_FAIL_RAW`、`INSTALL_PRE_BACKUP_FAILED`、`IMPORT_PRE_BACKUP_FAILED`（随主流程继续）。
- **sessions / cost 的"血缘不可用（未装桥插件）"裁决 = 1**：参数合法、命令可执行，缺的是运行环境前置数据（桥插件快照），
  与"没有有效备份 → 1"同口径；**不是 2**（不是参数写错，装插件后同一条命令即成功）。
- **未知失败面（防御分支）**：统一 1；构造不出场景的在覆盖表里写 not-covered + 原因，不静默。

## 未覆盖（not-covered）清单与原因

| 族 / 分支 | 原因 |
|---|---|
| RESTORE_ROLLBACK_FAILED | 需要"恢复失败 + 自动回滚失败"双重写盘故障；在本机只能破坏隔离根/权限来构造，且与 RESTORE_FAIL 共用 return，风险大于收益 |
| BACKUP_FAIL（各失败面） | 需要只读备份根/损坏的数据根；matrix 已覆盖成功面，失败面靠代码审阅 + rc 已为 1 的既有断言 |
| WIPE_FAIL | `GetFullPath` 对 DSH_HOME 异常取值在 .NET 8 被平台层兜住，防御分支不可达 |
| SHORTCUT_FAIL / AUTOSTART_FAIL | 会写**用户真实桌面/启动目录**，验收脚本不允许污染本机；不构造失败场景 |
| START_FAIL 的"启动命令发不出"/"30 秒未就绪" | 需要真实启动 dsh 子进程（动全局安装/端口），验收脚本不启动真实 dsh |
| STOP_FAIL 的"本程序自己"/"桌面端停止失败"/"12 秒未停" | 需要让 CLI 自身监听端口或杀真实桌面端；不安全，不构造 |
| BRIDGE_FAIL 的 auto-patch 失败 / 安装未成功 | 需要真实 dsh + pnpm + profile 写盘；会改用户 profile，不构造 |
| VERIFY_FAIL 的"无法计算哈希"/"拿不到自身路径" | 需要无法读自身文件/无法解析 MainModule 的异常环境；防御分支，不构造 |
| INSTALL/UPDATE 的非白名单失败面 | 会真的调用 npm 改全局包，验收脚本不执行 |
| BKDEL_FAIL / BKEXPORT_FAIL 的"删后仍在"/"导出失败" | 需要平台层写盘失败（只读盘/被杀进程），不稳定；用法与拒绝面已覆盖 |
